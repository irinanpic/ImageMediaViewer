# ImageMediaViewer 機能仕様書 (Specification)

本書は、軽量クロスプラットフォーム画像カタログ＆メディアビューア **ImageMediaViewer** の機能仕様および非機能要件を定義する公式仕様書です。

---

## 1. システム概要と基本設計思想

### 1.1 プロジェクトの目的
**「複数フォルダを横断したシームレスかつ高速な時系列画像閲覧体験」** を現代の技術（Rust + React + WebP）で実現し、大量の写真や画像を快適に閲覧・整理できる環境を提供することを目的とします。

### 1.2 コア設計思想
1. **元画像ファイルの非破壊保護 (Read-Only Guarantee)**:
   * 元画像ファイルへの書き込み、変更、移動、削除は行いません。
   * アプリが書き込みを行うのは、SQLite カタログデータベース（`catalog.db`）およびサムネイル専用キャッシュデータベース（`thumbnails.db`）のみです。
2. **カタログ・サムネイルの再生成可能性**:
   * カタログDBやサムネイルはすべて「再生成可能なキャッシュ」として位置づけられます。万一キャッシュが失われても、元ファイルから再構築が可能です。
3. **サムネイル分離による高速な閲覧速度**:
   * タイムライン一覧表示時は元画像ファイルを開かず、高速な軽量 WebP サムネイルのみを用いて描画します。
   * 元画像本体を開くのは、ユーザーがクリックして原寸拡大表示した際（ビューア）のみです。
4. **低オーバーヘッド・省メモリ**:
   * 10万枚規模の写真ライブラリであっても、メモリ消費を数十MB〜数百MB以内に抑え、仮想スクロールにより 60fps の滑らかな操作性を維持します。

## 2. 動作環境

| 項目 | 要件 / 対応環境 | 備考 |
| :--- | :--- | :--- |
| **対象 OS** | Windows 10 / 11 (x64)<br>macOS 12+<br>Linux (Ubuntu 22.04+)<br>Android 10+ (API 29+) | Windows 11 および Android 13+ を主要環境として最適化 |
| **ランタイム** | 独立デスクトップウィンドウ（Tauri v2 Native）<br>Android APK パッケージ | ポートレス一体型（Tauri IPC / カスタムプロトコル `thumb://`, `original://`） |
| **対応画像フォーマット** | JPEG, PNG, WebP, GIF, BMP, CLIP (.clip) | 標準デコーダおよび独立外部バイナリプラグイン（Windows: .dll, Android/Linux: .so, macOS: .dylib）により対応 |
| **最大処理画像数** | 100,000 枚以上（検証済み） | 仮想スクロールによりDOM数・メモリを一定化 |

## 3. 機能要件一覧 (Functional Requirements)

### 3.1 監視フォルダ管理
* **F-01 フォルダ登録・解除**:
  * ユーザーはエクスプローラー等からのドラッグ＆ドロップ、または選択ダイアログにより任意のローカルフォルダ（複数可）を登録・解除可能。
  * **OSドラッグ＆ドロップ自動パス取得**: エクスプローラー等からフォルダをドロップした際、OS（Tauri `onDragDropEvent`）から絶対パスを自動検出し、手動パス入力を必要とせず即座に自動登録。Webブラウザ利用時も既存監視フォルダの親階層から初期値を推測サジェスト。
  * フォルダ解除時も元画像ファイルは削除されず、カタログDB内の登録情報のみが安全に削除されます。
* **F-02 並び替え (Drag & Drop)**:
  * サイドバー内でフォルダをドラッグ＆ドロップして任意の表示順序に並び替え可能。
* **F-03 自動走査・差分インデックス**:
  * 初回登録時は高速再帰走査により全画像を自動インデックス。
  * 2回目以降はファイル更新日時（mtime）およびサイズ（size）の比較による高速差分スキャンを実施。
* **F-04 アイドル時自動チェック**:
  * ユーザーが操作を行っていないアイドル状態（45秒以上無通信）を検知すると、低優先度で登録フォルダ内の更新を自動チェック。
* **F-05 オフラインフォルダ保護**:
  * 外付けHDDやネットワークドライブが切断された場合、登録レコードを削除せず「オフライン」として保護し、キャッシュ済みサムネイルによる閲覧を継続可能。

### 3.2 超高速タイムライン一覧表示
* **F-06 仮想スクロール (Virtual Scrolling)**:
  * 何万枚の画像が存在しても、画面内に見えているセル＋前後数行のみを DOM 描画。
  * ウィンドウサイズ（幅）に応じて 4列 → 6列 → 8列 → 12列 と並び枚数が自動追従。
* **F-07 高速スクロールバー (タイムラインスクラバー)**:
  * 画面右端にマウスドラッグ可能な高速スクロールレールを配置。
  * つまみドラッグ中、左側に「該当日付（例: 2024-05-12）」および「通し枚数（例: 1,450 / 45,000枚）」がフローティングバッジとしてリアルタイム追従。
* **F-08 しおり（ブックマーク）機能＆高精度復元**:
  * 閲覧中の位置（スクロール位置、日付、画像通し番号、フォルダ絞り込み、ソート順）をワンクリックで保存・命名。
  * **ビューポート左上画像アンカーによる高精度復元**: スクロール位置の記録時、overscan を除外したビューポート最上端の表示行・先頭画像の通し番号（`imageIndex`）を特定して記録。ウィンドウ幅やズーム倍率の変更により列数が変化しても、該当画像の現在行を動的逆引きして最上端へ正確にスクロール復元。
  * **SQLite DB への永続化**: しおりデータはブラウザの揮発性ストレージではなくバックエンドの SQLite（`bookmarks` テーブル）へ保存され、アプリ再起動・OS再起動後も確実に保持。
  * **既存ローカルデータの自動移行**: 以前のバージョンでブラウザに保存されていたしおりデータも初回起動時に自動検知して DB へ移行。
  * しおり一覧から選択することで、いつでも瞬時にその閲覧位置へジャンプ・復帰可能。
* **F-09 ソート順切替**:
  * 撮影日時 降順（新しい順）
  * 撮影日時 昇順（古い順）
  * 登録フォルダ順（フォルダ別グループ表示）
  * ファイル名 昇順（A → Z）
  * ファイル名 降順（Z → A）
* **F-10 ズームスライダー (表示サイズ変更の一本化)**:
  * 下部ステータスバーのスライダーまたはマウスホイール連動により、サムネイル表示サイズ（80px 〜 320px）を動的に拡大・縮小可能。
  * 冗長性を排除するため、上部ツールバーおよびタイムライン画面内の拡大縮小バーを廃止し、ステータスバーへ一本化。
* **F-11 高速移動時のキューパージ＆現画面優先**:
  * スクロール速度が 800px/s を超える急激な移動時は、画面外に流れた古いサムネイル生成要求を自動破棄。
  * スクロール停止後、現在見えている位置のサムネイル生成および読込を最優先で再開。
* **F-12 複数画像選択 (Multi-Select) ＆ ムードボード一括登録**:
  * **個別選択トグル**: `Ctrl + クリック`（Mac: `Cmd + クリック`）またはサムネイル左上のチェックボックスバッジにより、個別画像の選択/解除をトグル。
  * **ドラッグ矩形選択 (ラバーバンド選択)**: グリッド背景をマウスドラッグすることで矩形枠を描画し、枠内に接触した複数画像をリアルタイムに範囲選択。
  * **全選択 / 全解除**: `Ctrl + A` によるロード済み画像全選択、`Esc` キーまたは解除ボタンによる一括選択解除。
  * **一括アクションバー**: 画像選択時、タイムライン最上部に「○枚選択中」「➕ ムードボードに登録」「✕ 選択解除」フローティングバーを常時表示。
  * **ムードボード一括投入**: 上部ボタンまたはツールバーの「ボードに追加 (○枚)」からダイアログを開き、選択した複数画像をムードボードへ一括配置。

### 3.3 サムネイル生成＆キャッシュパイプライン
* **F-13 サムネイル専用DB (thumbnails.db) へのBLOB保存**:
  * 10万枚規模での微小ファイル大量生成を回避し、SQLite 公式ベンチマークに基づく 35% 読み出し高速化およびゼロコピー mmap 読み出しを実現。
  * `WITHOUT ROWID` による B-Tree リーフ直接格納、8KB ページサイズ、256MB mmap、WAL モードを採用。
* **F-14 実アクセス時更新検知 (On-Access Change Detection)**:
  * サムネイル要求時（`/thumbs/:id`）または原寸表示時（`/raw/:id`）に、実ファイルのサイズ・更新日時（mtime）をマイクロ秒単位で軽量確認。
  * 画像の追記・上書きが検知された場合、新 `quick_hash`・寸法・EXIF を再計算してカタログDBを更新し、最新サムネイルを高優先度で自動再生成。
  * CAS（コンテンツアドレス）原則により、古いハッシュのサムネイルBLOBは他画像が共有している可能性があるため即時削除せず維持。
* **F-15 孤立サムネイル回収 (Garbage Collection: GC)**:
  * 画像更新や削除によって全画像から参照されなくなった孤立サムネイルBLOBを、アイドル時にバックグラウンドで安全に一括回収。
* **F-16 EXIF 内蔵サムネイル最優先抽出**:
  * デジタルカメラ等の撮影データ（JPEG等）に含まれる EXIF IFD1 埋め込みサムネイルを最優先で検出・利用。
  * 数千万画素の元画像フル展開（数秒、数百MB）をスキップし、1〜3ミリ秒で WebP サムネイルを高速生成。
* **F-17 未生成サムネイルの自動検知＆生成**:
  * タイムライン閲覧中にサムネイルの無い画像を見つけた場合、自動的に高優先度キューへ投入してサムネイル化を開始。
  * 過去に失敗（2）していた画像も自動再作成対象に復帰。
* **F-18 手動一括再作成**:
  * サイドバーの「再作成」ボタンから、未生成・失敗サムネイルの一括バックグラウンド再作成を要求可能。

### 3.4 詳細画像ビューア
* **F-19 原寸画像シームレス表示＆高品質バイキュービック拡縮**:
  * サムネイルクリックでモーダル全画面ビューアを開く。
  * まずキャッシュ済みサムネイルを即座に表示し、バックグラウンドで原寸画像（`/raw/:id`）を読み込んで高解像度へシームレスに差し替え。
  * **高画質拡縮レンダリング**: タイムライン（速度最優先・軽量WebP）と異なり、しっかり鑑賞・確認するビューアでは品質を最優先。`imageRendering: auto`（バイキュービック/バイリニア補間）、3Dハードウェア加速レイヤー、同期デコード（`decoding="sync"`）を適用し、縮小・拡大時のジャギーやボケを排除。
* **F-20 非破壊操作＆原寸ピクセル等倍ズーム (1:1)**:
  * **原寸等倍表示**: 元画像の解像度とビューポート寸法から、元画像の1ピクセルがディスプレイの1ピクセルに一致する正確なスケールを算出して表示（`1` キー、ツールバーボタン、ダブルクリック連動）。
  * 拡大・縮小（マウスホイール / ピンチ、最大16倍まで細部確認可能）
  * パン（ドラッグ移動）
  * 90度回転（時計回り / 反時計回り）
  * 左右反転（水平反転） / 上下反転（垂直反転）
  * 元ファイルは変更せず、GPU Transform による即時プレビュー。
* **F-21 ナビゲーション (ホバーフェードイン＆左右クリック連動)**:
  * 通常閲覧時は前へ・次へボタン（◀ / ▶）を非表示にして画像鑑賞の没入感を保護。
  * 画面左右端の検知エリアへマウスホバーした際のみ、半透明の◀ / ▶ボタンがフェードイン表示。
  * ボタン自体のクリックに加え、画面左右端の検知エリア全体のクリックでも即座に前後の画像へめくれる直感的なページ送り操作を提供（モバイルや大画面での快適なめくり操作を両立）。
  * キーボード `←` / `→` キーおよびスワイプジェスチャーでの前後移動にも対応。
  * `Esc` キーでビューアを閉じ、タイムラインの直前位置へ復帰。
* **F-22 共通詳細情報パネル / エクスプローラ連携**:
  * タイムライン閲覧時とムードボード選択時で共通化された高品質情報パネルコンポーネント（`ImageDetailPanel`）を提供。
  * 基本情報: ファイル名、撮影日時（EXIF抽出値 / ファイルmtime）、解像度、絶対パス。
  * **画像フォーマット情報**: 拡張子およびMIMEタイプから自動判定（JPEG, PNG, WebP, GIF, BMP, TIFF, AVIF, HEIC等）。
  * **可逆 / 非可逆 (Lossless / Lossy) 判定**: 画像形式ごとの圧縮特性を明示（PNG/BMP/GIFは可逆、JPEGは非可逆、WebP等はメタデータ・拡張子により判定）。
  * **ファイルサイズ & 圧縮率情報**: 実ファイルサイズに加え、非圧縮24bit RGB生データサイズ（幅×高さ×3バイト）との比較による削減率（%）、生データ比（%）、および 1ピクセルあたりの実効ビット数（bpp: bits per pixel）を算出表示。
  * **OSファイルマネージャ連動**: 「フォルダで表示」ボタンにより、OSのエクスプローラーで該当ファイルを選択状態で表示。

### 3.5 ムードボード (自由配置キャンバス)
* **F-23 自由配置・無限キャンバス（原寸高画質レンダリング＆高精度操作）**:
  * 複数の写真を自由に配置し、アイデア整理やコラージュを作成可能。
  * **原寸ファイルベースの高品質描画**: タイムラインのようなサムネイル縮小画像ではなく、原寸画像（`/raw/:id`）から直接読み込み、`image-rendering: auto`（バイキュービック/バイリニア補間）による高精細な拡大縮小表示を提供。
  * **高精度変形操作（回転バグ解消）**: 各アイテムの位置（X, Y）、拡大率、回転角度を非破壊で調整。回転ハンドルドラッグ時はアクティブアイテム参照をリアルタイム同期し、未選択の他画像が誤って回転する不具合を解消。
* **F-24 レイヤー重なり順 (Z-Index) 変更**:
  * 選択アイテム（画像・メモ）の重なり順を「最前面へ」「前面へ」「背面へ」「最背面へ」自由に変更可能。
* **F-25 ドラッグ矩形クリッピング**:
  * 画像上をマウスドラッグして矩形を指定し、必要な部分だけを切り抜いてキャンバス上に配置可能。
* **F-26 画像反転 (水平/垂直)**:
  * ムードボード上でアイテムごとの左右反転・上下反転に対応。
* **F-27 画像詳細情報表示**:
  * ムードボード上で選択した画像の詳細情報を、タイムライン閲覧時と同一の共通情報パネルでキャンバス右下に展開表示可能。
  * アクションバーの「ℹ️ 詳細情報」ボタンまたはショートカットキー `I` で即座に表示切替。
* **F-28 テキストメモ機能 (矩形付箋の自由配置・編集・複数行対応)**:
  * ムードボード上の任意の場所にテキストメモ矩形（付箋）を複数自由に配置可能。
  * マウスドラッグによる自由な移動、右下ハンドルによるリサイズに対応。
  * `Enter` キーでの改行による複数行テキストの記録・スクロール閲覧、ダブルクリックまたはアクションバーからのインラインテキスト編集（`Ctrl+Enter` で確定保存、`Esc` でキャンセル）。
  * キャンバス余白クリック、他アイテム・メモ選択、ツールバー完了ボタン押下、画面離脱時にも編集中の最新テキストが確実に自動確定保存される堅牢なRef同期構造。
  * カラーパレットからメモの背景色（イエロー、ブルー、グリーン、ピンク、パープル、ダークグレーの6色）をワンクリック変更。
  * 画像アイテムとメモ矩形を統合したレイヤー重なり順（Z-Index）制御、誤操作防止ロック、削除に対応。
* **F-29 自動並び替え機能 (Auto-Arrange / 被り防止タイル整列)**:
  * 画像アイテムと付箋メモが重複しないよう自動配置する手動実行機能。
  * コントロールバーの「📐 自動並び替え」ボタンから明示的に実行（ユーザーが意図して重ねた自由配置を保護するため）。
  * 各要素のスケール適用後サイズに基づく行ベース・フローパッキング（マージン 28px、回転角 0° リセット）を実施。
  * 整列完了後、全アイテムの外接矩形を算出してキャンバス中央へカメラを自動追従（Zoom to Fit: `pan`, `zoom`）。
  * 整列後の新座標を SQLite DB（`board_items`, `board_notes`）へ一括永続化。
* **F-30 自動永続化**:
  * 画像アイテムの配置・変形・クリッピング情報、およびメモ矩形情報（`board_notes` テーブル）を SQLite DB へ自動保存。タイムラインとボードを行き来しても状態を確実に保持。

### 3.6 システム・ライフサイクル管理
* **F-31 ウィンドウ状態の復元**:
  * 前回のウィンドウサイズ、位置、最大化状態を起動時に復元。
* **F-32 ポートレス一体化＆タスクトレイ常駐制御（常駐切替・設定永続化）**:
  * **ポートレス一体型アーキテクチャ**: TCP/IPポート（14201 等）を開かないポートレス構成。Tauri Native IPC（メモリ内メッセージパイプ）およびカスタム URI スキーム（`thumb://`, `original://`）により全通信を完結させ、ポート競合・ファイアウォール警告を回避。
  * **タスクトレイ常駐ライフサイクル**:
    * メインウィンドウの「×」ボタンを押した際、デフォルトでウィンドウを非表示（Hide）にしてタスクトレイに常駐。
    * タスクトレイアイコンの左クリックまたは右クリックメニュー「クライアントを開く」により、非表示中のメインウィンドウを最前面に即座に再表示。
    * アプリケーションの終了は、タスクトレイ右クリックメニューの「終了」を実行。
  * **「常駐する」設定メニューと自動永続化**:
    * タスクトレイ右クリックメニューに「✔ 常駐する」（チェック項目）を搭載。デフォルトは **ON**。
    * クリックにより ON / OFF を切り替え可能で、設定値は `%APPDATA%\com.imagemediaviewer.desktop\app_settings.json` へ自動保存・次回起動時に復元。
    * **OFF の場合**: メインウィンドウの「×」ボタンを押すと、トレイに残らずアプリケーション全体が即座に終了。
  * **二重起動ガード**: 既にアプリが起動している状態で再度実行された場合、多重起動を行わず既存のメインウィンドウを最前面に表示して安全に終了。
  * **標準インストーラー仕様および同梱配布構成**: Windows NSIS インストーラーは `perMachine` モード（管理者権限で `C:\Program Files\ImageMediaViewer` に配置）を標準採用。ビルドは npm スクリプト `npm run build:installer` により、フロントエンドのビルドおよび Tauri バックエンドのリリースコンパイル・インストーラーバンドル（`ImageMediaViewer_<version>_x64-setup.exe`）までをワンコマンドで生成。また `bundle.resources` マッピング（`"../plugins": "plugins"`）により、インストール先直下（`\ImageMediaViewer\plugins\`）にプラグインサンプルコード、設定例、開発ガイド（`README.md`）を同梱展開。
* **F-33 通信状態監視およびクライアント再接続 (ヘルスチェック＆多重起動防止型自動復帰)**:
  * 画面上部右側に常時通信状態インジケータ（🟢 接続中 / 🟡 接続確認中 / 🔴 サーバー切断）を表示。
  * 定期的なハートビート通信によりサーバー死活をリアルタイム監視。
  * サーバー切断時は警告バッジおよびワンクリック再接続ボタンを提供し、サーバー復帰時に自動でタイムラインデータを再同期。
  * **多重起動防止カスタムプロトコル連携**: カスタムプロトコル `imagemediaviewer://launch` により、ブラウザ側からサーバーのみをワンクリック起動（クライアント画面の多重起動を防止）。不可視 iframe を用いた安全なバックグラウンド呼び出しにより、Web ページのコンテキストやタイマー破棄を防止。
  * **プロトコルの自動登録と自己修復**: ランチャー（`run.ps1`）実行時およびバックエンドバイナリ（`image-media-viewer.exe`）起動時の双方で、Windows レジストリ（`HKCU:\Software\Classes\imagemediaviewer`）へのプロトコル登録状況を自動判定。未登録またはパス更新時に管理者権限不要で自身の EXE パスを直接ターゲットとして自動登録・自己修復を実施。インストーラー経由でインストール・起動した場合も追加設定なしでプロトコル連携が正常に機能。プロトコルハンドラ呼び出し時の URI 引数 `%1` に対する安全なエスケープ処理を実装。
  * **OS自動判別によるクロスプラットフォーム回復対応**: ユーザーの閲覧環境（Windows / macOS / Linux）を自動判定し、最適なサーバー起動スクリプト（`.\run-server.bat` または `./run-server.sh`）のコピーコマンドを提示。
  * **段階的自動再接続と起動中フィードバック**: サーバー起動トリガー送信後、UI上で「サーバー起動を試行中...」とローディングインジケータを表示し、1.2秒、3秒、5秒、7.5秒の間隔でバックグラウンド再接続を自動リトライし、スムーズな復帰を実現。万一自動起動しない場合もワンクリックで起動コマンドをコピーして手動実行可能。
* **F-34 ログ出力・エラー診断とサムネイル生成失敗監視**:
  * バックエンドログの常時ファイル出力（`%APPDATA%\com.imagemediaviewer.desktop\logs\app.log`）および直近ログのメモリリングバッファ管理。
  * サムネイル生成でファイル破損・0バイト空ファイル・未対応形式等により失敗した画像（`thumb_status = 2`）のエラー内容・パス・画像IDをロギングし、未生成（0）と明確に分離して無限補充ループを防止。
  * 進捗集計（`ThumbProgress`）に `failed` 件数を追加し、UI上で「○件完了 / △件失敗」のように生成進捗を明示。
  * クライアント上に「システムログ & エラー診断モーダル」を実装。失敗画像一覧（パス、0バイト警告、エクスプローラ表示）、直近ログの確認・絞り込み、ログコピー、ログフォルダ直接開放（OSファイルマネージャ連動）を提供。
  * タスクトレイメニューにも「ログフォルダを開く」項目を常設。
* **F-35 バックグラウンド省電力・静音スロットリング制御**:
  * 長時間常駐時のCPU過熱・ファン騒音を防止するため、アイドル時のフォルダ差分走査およびバックグラウンドサムネイル生成にスロットリングを適用。
  * アイドルフォルダ走査（5分間隔）時、100ファイル走査毎に 5ms の休止を挿入し、CPU負荷を 1〜3% に抑制。
  * パイプラインがアイドルになってから30秒間のクーリング待機を経てからバックグラウンド走査を開始。
  * バックグラウンド走査中にユーザー操作（サムネイル要求・スクロール等）を検知した場合、即座に走査を安全中断してCPUを最優先でユーザーに明け渡す。
  * バックグラウンドでの未生成サムネイル生成時、1枚処理毎に 20ms のクーリング休止を挟み、CPU負荷集中とファンの強回転を防止（表示中の画像は休止なしで最速生成）。
  * 全件生成完了後のアイドル待機時、ワーカースレッド群を 60 秒の静止待機とすることで、常駐時 CPU 使用率 0.0% を実現。
* **F-36 仮想スクロール限界突破スケール圧縮＆O(1)レンダリング**:
  * 推定全高が800万px（ブラウザの描画限界）を超える超大規模ライブラリにおいて、コンテナ実高さを800万pxに収めるスケール圧縮（`scaleCompression`）および実スクロール・仮想スクロールの双方向比率マッピングを適用。行自体の高さを維持したままビューポート相対座標へ配置することで、過密境界や行同士の重複・空白化を防止。
  * 仮想スクロール行定義（`TimelineRow`）に所属日付を常時保持し、可視位置特定（`setCurrentVisibleInfo`）時の数千行におよぶ逆方向探索ループを排除して O(1) アクセスを実現。
  * `overscan` 行数を 12 から 4 行へ最適化し、同時マウントセル数とDOM負荷・メモリ消費を大幅に削減。
* **F-37 モバイル操作系統合（Android 13+ 権限・戻るボタン・タッチ長押し・ドロワー）**:
  * **Android 13+ (API 33+) 細分化メディア権限対応**: `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` に対応し、Android 13以降の端末でも写真フォルダを安全に取得。
  * タイムライン画像セルのタッチ長押し（500ms）による直感的な複数選択トグルとバイブレーションフィードバック。
  * コンパクト（モバイル）表示時、下部ステータスバーに縮小・拡大ボタン（列数増減ボタン）を配置し、片手での表示密度変更を可能に。
  * Android OS のシステム戻るボタンおよびエッジスワイプジェスチャーを検知（`useBackNavigation`）し、最上位ダイアログ（Log / AddToBoard）→ 画像詳細ビューア → 複数選択状態 → ムードボード画面 → モバイルドロワーを階層的に1段ずつ安全に戻す操作性を実現。UIボタンでのクローズ時もブラウザ履歴スタックと同期。
* **F-38 パイプライン・I/O最適化（キャッシュ共有・複合インデックス Migration v7）**:
  * **クイックハッシュによるキャッシュ共有**: 同一内容の画像（同一 `quick_hash`）が存在する場合、既存サムネイルBLOBを再利用し、重複生成の無駄をスキップ。
  * **SQLite Migration v7 複合インデックス**: `idx_images_folder_taken`, `idx_images_mtime`, `idx_images_file_size`, `idx_images_file_name` を追加し、フォルダ別・サイズ別・名前順ソートクエリをインデックススキャン化。
  * フォルダ走査（walker）時、1画像につき単一の `File::open` ハンドルからクイックハッシュ算出とExif/画像寸法抽出を連続実行し、ディスクI/O回数を半減。
  * 走査時の削除検知において、既存DBマップから走査済みキーをインプレースで削除する方式とし、メモリ消費を半減。
  * サムネイル進捗をバックエンドのアトミックカウンタで常時カウントし、テーブルスキャンを排除して O(1) メモリアクセス化。
  * クライアントの 1.2秒ポーリングおよび 2.5秒HTTPハートビートを廃止し、200ms スロットルのイベント駆動（`scan:progress`, `thumb:progress`, `catalog:changed`）によるCPU負荷低減を達成。
  * ムードボードキャンバスでの LOD（Level of Detail）表示により、通常時は軽量サムネイル、選択・クロップ・高倍率時のみ元画像をロードしてメモリを節約。
* **F-39 クロスプラットフォーム・リリースビルド独立保証**:
  * Windows ホスト環境での Android NDK クロスコンパイル時における MSVC リンカーフラグ誤適用を隔離・防止（`build.rs` 内で `CARGO_CFG_TARGET_OS` / `CARGO_CFG_TARGET_ENV` を動的検証）。
  * Windows NTFS ReadOnly 属性付加による `autocfg` パニック（`output path is not a writable directory` / code 101）の自動事前解除機構（`clean-target-readonly.mjs`）をビルドパイプラインへ統合。
  * Windows インストーラー（NSIS: `npm run build:installer`）および Android Release APK（`npm run build:android:release`）の双方を安定して独立生成可能。
* **F-40 完全分離型動的バイナリプラグインアーキテクチャ (Isolated Binary Dynamic Plugins)**:
  * アプリ本体から特定形式のデコード・抽出ロジック（SQLite 解析等）を完全に分離・撤廃し、独立バイナリ（C-ABI動的ライブラリ `cdylib` および独立実行バイナリ `bin`）として別クレート/別ターゲットでビルド・配置・動的ロードする完全分離型アーキテクチャを導入。
  * `ImageFormatPlugin` トレイト、プラットフォーム別バイナリ解決機能を持つ汎用抽出エンジン（`binary`, `binary_slice`, `command`）、および動的プラグインレジストリ `FormatPluginRegistry` を実装。
  * `binary` 抽出タイプでは、`libloading` によるインメモリ C-ABI 直接呼び出し（`imv_plugin_init`, `imv_plugin_extract_metadata`, `imv_plugin_extract_preview`, `imv_plugin_free_buffer`）を最優先とし、未ロード時やプロセス分離環境では CLI コマンド（`metadata`, `preview-pipe`）へのフェイルセーフな自動フォールバックを完備。

  * **スキャナーの動的走査拡張と確実なインデックス反映**:
    * プラグイン探索パス（実行ファイル直下、リソースディレクトリ、親ディレクトリ、開発環境、ユーザーデータディレクトリ `%APPDATA%/.../plugins/`）を網羅的に走査し、有効化された全プラグインの拡張子（`extensions`）をスキャナー（`walker.rs`）へ動的に合流。
    * 監視起点フォルダ（`entry.depth() == 0`）がドット始まりの場合に走査が破棄される問題を根本解決。
    * アプリ起動時のバックグラウンド自動差分走査により、プラグイン追加後のファイル取り込みを即座に実現。
  * **プラグイン標準同梱および配布**:
    * インストーラー配布物に `plugins/` ディレクトリを同梱（`bundle.resources`）。インストール先直下に `plugins/README.md`（プラグイン開発ガイド）、`plugins/clipstudio/plugin.json`、`plugins/clipstudio/imv_clipstudio.dll`、`plugins/clipstudio/clipstudio_plugin.exe`、`plugins/sample_format/plugin.json`、`plugins/app_settings.sample.json`、`plugins/action_plugins/custom_action_sample.json` を展開。
* **F-41 標準同梱 ClipStudio 形式 (.clip) 独立プラグイン (`plugins-src/clipstudio/`)**:
  * CLIP STUDIO PAINT ドキュメント形式（`.clip`）の抽出ロジックを本体コードから完全に分離し、独立クレート `plugins-src/clipstudio` として実装。
  * **デュアルターゲット出力**: `crate-type = ["cdylib", "rlib"]` および `[[bin]] name = "clipstudio_plugin"` により、C-ABI 動的ライブラリ（`imv_clipstudio.dll`）と CLI 独立実行バイナリ（`clipstudio_plugin.exe`）の双方をビルド・出力。
  * **自動ビルド＆同期パイプライン**: `scripts/build-plugins.mjs` を通じて、本体インストーラービルド時および `npm run build:plugins` 時に自動コンパイル・配置。
  * **CSFCHUNK 構造解析 & インメモリ SQLite デシリアライズ抽出**: `CHNKSQLi` チャンクを `sqlite3_deserialize` でインメモリ展開し、`CanvasPreview` テーブルの `ImageData` からオーバーフローページの混入のない PNG バイナリを高速抽出。非SQLiteチャンクやモック構造にはストリーミングシグネチャ探索へ自動フォールバック。
  * **IHDR チャンクによる O(1) 高速寸法抽出**: 抽出した PNG の先頭 16〜24 バイト（IHDR チャンク）からダイレクトに画像幅・高さをビッグエンディアン読取。
  * **WebP サムネイル自動生成 & 原寸プレビュープロトコル連動**: WebP サムネイルを生成して `thumbnails.db` へ格納し、原寸ビューワ表示時はカスタムプロトコル `original://` を通じて内蔵 PNG を透過返却。
  * **CLIP STUDIO PAINT 外部起動連携**: アプリケーション連携アクション（`action.open_clip_studio`）を通じて、OSの関連付け起動または標準インストールパスから対象 `.clip` ファイルを直接開く操作をサポート。
* **F-42 カスタム右クリックコンテキストメニューおよび外部アプリ連携**:
  * タイムライングリッドの画像セル（`GridCell`）および詳細画像ビューア（`ImageViewerModal`）上での右クリック（モバイル長押し）によるフローティングコンテキストメニュー表示。

  * **画面外はみ出し防止のクランプ制御**: ビューポート境界（上下左右）をリアルタイム検知し、画面端で開かれた場合でもメニュー全体が確実に画面内に収まるよう座標を動的補正。外部クリックおよび `Esc` キー押下による自動クローズを完備。
  * **標準組み込みアクション**:
    * 既定のアプリで開く (`open_file_with_default_app`)
    * CLIP STUDIO PAINTで開く (`open_in_clip_studio`、`.clip` ファイル時のみ動的表示)

    * ファイルパスをコピー (`action.copy_path`)
    * ボードに追加 (`action.add_to_board`)
    * ゴミ箱へ移動 (`trash_file`、OS標準のゴミ箱へ安全に退避し、カタログDBおよびUIから即時除去)
  * **ユーザー定義カスタム外部アプリ登録**:
    * 設定モーダル（`ContextMenuSettingsModal`）から、ユーザーが日常使用する画像編集ソフト・ビューワ等の実行ファイルパス、起動引数（`{path}` 置換）、対象拡張子フィルタリングを GUI 上で自由に登録・編集・削除可能。
    * 拡張子フィルタ（例: `clip, psd`）が指定されている場合、対象フォーマットの画像でのみメニュー項目が出現するスマートフィルタリングを実装。
* **F-43 アプリケーション設定（app_settings.json）とプラットフォーム抽象化レイヤー**:
  * アプリ設定構造体 `AppSettings`（常駐設定 `stay_in_tray`、言語 `locale`、有効化プラグイン一覧 `enabled_plugins`、カスタムメニュー項目 `custom_context_menu_items`）を導入。
  * **環境非依存・モバイル互換原則**:
    * `custom_context_menu_items` のデフォルト初期値は空配列 `[]` とし、Windows固有パス（`mspaint.exe` 等）などの環境依存設定をプリセットしない設計を徹底。
    * 設定ファイル（`app_settings.json`）にはユーザーが明示的に登録した項目のみを保存。
    * モバイル（Android）環境では外部プロセスコマンド起動やデスクトップ用ゴミ箱API（`trash` クレイト）をプラットフォーム抽象化レイヤーで安全に隔離し、OS共有インテント（`tauri_plugin_opener`）および標準ファイル削除へ自動フォールバック。
* **F-44 全プラットフォーム共通・独立外部バイナリプラグイン (Independent External Binary Plugins)**:
  * **本体コアの純化**: ビューワ本体コードベース（`src-tauri`）から特定ソフトウェア形式（CLIP STUDIO等）の知識やフォールバック処理を完全に排除し、純粋なプラグインホストに徹する。
  * **独立共有ライブラリ (cdylib)**: 各プラットフォーム向けに外部共有ライブラリ（Windows: `imv_clipstudio.dll`, Android: `libimv_clipstudio.so`, Linux: `libimv_clipstudio.so`, macOS: `libimv_clipstudio.dylib`）を独立ビルド。

  * **Android マニフェスト自動同期 (`MainActivity.kt`)**: 起動時に APK 内の `assets/plugins`（`plugin.json` 等）をアプリ内部ストレージ（`filesDir/plugins`）へ自動展開し、ファイル走査エンジンからの確実なプラグイン認識を保証。
  * **自動ビルド・APK 同梱連携 (`scripts/build-android.mjs`, `scripts/build-plugins.mjs`)**: Android APK ビルド時に NDK Clang を用いて `aarch64-linux-android` および `x86_64-linux-android` 向けにプラグインを自動コンパイルし、`src-tauri/gen/android/app/src/main/jniLibs/<abi>/` へ自動配置して APK へ同梱。

## 4. 非機能要件 (Non-Functional Requirements)

| 区分 | 要件項目 | 目標値 / 仕様 |
| :--- | :--- | :--- |
| **パフォーマンス** | 一覧表示レスポンス | キャッシュ済みサムネイル表示: **< 1ms** |
| | スクロール描画 | 仮想スクロールフレームレート: **60fps** 維持 |
| | サムネイル生成速度 (表示中) | EXIF内蔵抽出時: **1〜3ms / 枚**（CPUフル稼働・最優先） |
| | カタログインデックス | 50,000 枚の差分走査: **< 3秒**（フォアグラウンド時） |

| | ディスク消費 | WebP lossy (品質60): 平均 **15KB〜35KB / 枚** |
| | **CPU使用率 (アイドル常駐時)** | **0.0% 〜 0.1%** (ファン停止維持) |
| | **CPU使用率 (バックグラウンド走査時)** | **1% 〜 3%** (スロットリングによる静音維持) |
