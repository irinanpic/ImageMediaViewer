## 2. マイルストーン別実測ログ

### M0: PoC・計測 (Spike)
- **実施日**: 2026-10-03
- **環境**: Windows 11 (WebView2 / SQLite bundled WAL / Rust 1.98 / Node 24.15)
- **10万件ダミー投入 (tools/seed-catalog/seed.py)**:
  - 投入速度: **95,085 件/秒** (100,000件を1.05秒でDB投入完了)
  - サムネイルキャッシュ: 30種類のユニークWebP実ファイルを事前配置
- **SQLite クエリ性能 (tools/seed-catalog/bench_query.py)**:
  - 総件数カウント (`COUNT(*)`): **1.22 ms**
  - 日別サマリ集計 (`GROUP BY day ORDER BY day DESC`、1,002日分): **57.23 ms**
  - タイムライン中間ページング取得 (`OFFSET 50000 LIMIT 200`): **3.07 ms**
- **元ファイルの不変性・耐障害性**:
  - `cargo test --test pipeline_test` により、走査・サムネイル生成の前後で元ファイルのSHA256/BLAKE3ハッシュおよびmtimeが不変であることを検証済み。
  - 破損画像ファイル入力時もクラッシュやパニックを起こさず安全にエラーハンドリングされることを確認済み。
  - 超パノラマ画像（2560x100px）での長辺512px制限が意図通り機能することを確認済み。

### M1: 統合パフォーマンス改善（Phase 1〜3）
- **実施日**: 2026-10-15
- **環境**: Windows 11 (Tauri v2 / SQLite 3.45 / Rust 1.84 / React 18 / Vitest 3.2)
- **データベース & I/O 最適化**:
  - Migration v7 (`idx_images_folder_filepath`): 走査時パス逆引き・突き合わせを 10万件下でも O(1) インデックス探索化。
  - キャッシュ共有 (`cache_key = quick_hash`): 同一ハッシュ画像のサムネイル再生成をスキップ。
  - 走査エンジン (`walker.rs`): `File::open` 1回化により、ファイルオープンおよびOSディスクハンドル確保回数を 50% 削減。削除検知用 `HashSet` 撤廃により走査時メモリ消費を半減。
  - プリペアドステートメントキャッシュ (`prepare_cached`): タイムライン取得・サマリ集計・ボードクエリのパースコストを削減。
  - 低優先度サムネイルバッチ (`flush_low_batch`): 100件単位または 1,500ms スロットリングでコミットし、トランザクション発行回数を抑制。
- **進捗管理と常時常駐化**:
  - アトミックカウンタ (`thumb_total`, `thumb_done`, `thumb_failed`): サムネイル進捗集計の SQLite テーブルスキャンを排除し、**< 0.001 ms (O(1) メモリアクセス)** を実現。
  - イベント通知スロットリング: 200ms 間隔で `thumb-progress` をフロントエンドへ送出。
  - クライアント側 1.2秒ポーリング (`setInterval`) および 2.5秒HTTPハートビートを廃止。常駐時のCPUウェイクアップを排除。
- **仮想スクロール & UI**:
  - 仮想スクロール高さスケール圧縮: 全高 8,000,000px を超える大規模ライブラリでもブラウザレイアウト限界を回避して滑らかに描画。
  - O(1) 日付ヘッダ参照: 可視位置メタデータ取得時の過去行ループを撤廃し、スクロール時の JS メインスレッド負荷を低減。
  - `overscan: 4`: DOM要素数を適正化し、メモリ使用量と初期レンダリングを高速化。
  - 高速スクロールキューパージ (`clearQueue`): 400ms スロットリングにより IPC フラッディングを防止。
  - ムードボード LOD: 俯瞰時はサムネイル、選択・拡大時のみ元画像を読み込み、メモリ消費を大幅削減。
- **テスト検証結果**:
  - Rust ユニット＆結合テスト: **56 / 56 tests passed** (全テスト成功)
  - フロントエンド Vitest テスト: **63 / 63 tests passed** (全テスト成功)
  - TypeScript & Vite ビルド: **エラー 0 件 (正常終了)**

### M2: リリース前品質チェック改修 & 10万枚規模・長時間稼働最終仕上げ
- **実施日**: 2026-10-17
- **バックエンド & プラグイン最適化**:
  - `ThumbBinaryLruCache` 世代カウンタ方式により Mutex ロック内の `get` / `put` / `remove` を $O(N)$ 線形探索から **償却 $O(1)$** へ改善。
  - `thumb_lookup_cache` に上限（PC: 20,000件 / モバイル: 5,000件）を導入し、長時間稼働時のヒープ肥大化を防止。
  - `walker.rs` の走査ループ中における 1.5秒ごとの `bump_catalog_version()` / `catalog-changed` 発火を廃止し、走査完了時の1回に集約。走査中の `timeline_summary_cache` / `thumb_lookup_cache` 全消去と `GROUP BY` 再集計スパイクを解消。
  - `.clip` プラグイン（`plugins-src/clipstudio`）および `DynamicFormatPlugin`（`runtime.rs`）に `(path, file_size, mtime)` キーの短命リングキャッシュ（最大8件）を導入し、メタデータ抽出と直後のサムネイル生成での二重抽出を排除（スキャン＋サムネイル生成のI/O・CPU負荷を半減）。
  - `server.rs` の変更検知を単一 `File::open` + プラグイン対応メタデータ抽出に統一し、`/api/timeline/summary` にインメモリキャッシュを適用。
- **フロントエンド & モバイルUX最適化**:
  - `GridCell.tsx` の `loadedThumbUrls` に最大 10,000 件の FIFO 上限を設定。
  - `SharedPageCacheManager.getAllLoadedIds()` を新設し、`Ctrl+A` 全選択時の `totalImages` ループと LRU 順序破壊を解消。
  - `action.trash_file` に確認ダイアログ（モバイルでは物理完全削除の警告）と削除後のビューア・選択状態クリーンアップを実装。
  - Android 11+ Scoped Storage 向けの `MANAGE_EXTERNAL_STORAGE` 権限確認・設定誘導コマンド、および `extractNativeLibs="true"` / `useLegacyPackaging = true` によるプラグイン `.so` 確実展開を構成。
