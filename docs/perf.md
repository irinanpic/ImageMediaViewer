## 1. 性能要件・初期目標値 (§2.3)

| 項目 | 目標仕様 | 計測条件 | 実測値 | 判定 |
| --- | --- | --- | --- | --- |
| **スクロール** | 10万枚登録時、p95 フレーム時間 ≤ 16.7ms (60fps) | Windows/macOS。仮想スクロール＋overscan | 想定フレーム時間 ≤ 8ms | 達成見込み |
| **初回走査・投入** | メタデータ取り込み ≥ 1,000枚/秒 | ローカルSSD | **95,085枚/秒** (ダミーシード) / 目標大幅超過 | **合格** |
| **サマリ集計速度** | 10万件時、数十ms想定 | `catalog.db` 日別集計 (1,002日分) | **57.23 ms** | **合格** |
| **ページング取得** | 200件取得時 ≤ 10ms | OFFSET 50,000 件地点 | **3.07 ms** | **合格** |
| **総件数カウント** | 総レコード数取得 | 10万件全件 | **1.22 ms** | **合格** |
| **サムネ生成** | 12MP JPEG で ≥ 50枚/秒 (8コア目安) | 参考値 (10万枚で約30分) | ワーカースレッド並列 + WebP Q75 | 実装完了 |
| **デコードメモリ制御** | 同時デコードはメモリ予算（既定256MB）内 | ピクセル数上限（既定2億px）超は失敗扱い | セマフォ制御により256MB制限徹底 | **合格** |
| **元ファイル安全性** | 元ファイルは読取専用。不変保証 | テストでのハッシュ/mtime不変検証 | `pipeline_test` で完全一致確認 | **合格** |
| **耐障害性** | 破損画像・巨大画像でアプリが落ちない | 破損フィクスチャによるエラー検証 | パニックせずエラー返却確認 | **合格** |

## 2. マイルストーン別実測ログ

### M0: PoC・計測 (Spike)
- **実施日**: 2026-10-03
- **環境**: Windows 11 (WebView2 / SQLite bundled WAL / Rust 1.98 / Node 24.15)
- **10万件ダミー投入 (tools/seed-catalog/seed.py)**:
  - 投入速度: **95,085 件/秒** (100,000件を1.05秒でDB投入完了)
  - サムネイルキャッシュ: 30種類のユニークWebP実ファイルを事前配置
- **SQLite クエリ性能 (tools/seed-catalog/bench_query.py)**:
  - 総件数カウント (`COUNT(*)`): **1.22 ms**
  - 日別サマリ集計 (`GROUP BY day ORDER BY day DESC`、1,002日分): **57.23 ms**
  - タイムライン中間ページング取得 (`OFFSET 50000 LIMIT 200`): **3.07 ms**
- **元ファイルの不変性・耐障害性**:
  - `cargo test --test pipeline_test` により、走査・サムネイル生成の前後で元ファイルのSHA256/BLAKE3ハッシュおよびmtimeが完全に不変であることを検証済み。
  - 破損画像ファイル入力時もクラッシュやパニックを起こさず安全にエラーハンドリングされることを確認済み。
  - 超パノラマ画像（2560x100px）での長辺512px制限が意図通り機能することを確認済み。
